## Overview

A transaction is a list of parts, such as `output(...)`. Give the list and a payer to `builder.build()` and you get a `BuiltTx` to sign and submit. The builder selects inputs, adds change and sets the fee. For scripts it also adds collateral and execution units, so you set none of them.

Examples use these names, which your application defines:

- `provider`, `wallet` - a provider such as `BlockfrostProvider` ([Providers](/providers)), and a `MeshWallet` or `BrowserWallet` ([Wallets](/apis/wallets))
- `changeAddress` - the wallet's address, from `await wallet.getChangeAddress()`
- `recipient`, `partner` - addresses
- `utxo`, `utxos` - one output of yours and a list of them, as Mesh `UTxO`s (an unspent output: coins held at an address)
- `unit` - a policy id plus an asset name in hex
- `params`, `costModels` - protocol parameters (`Protocol`) and cost models (`number[][]`)
- `builder` - the one made in the next section

## Create a Builder

`network` is required: `"mainnet"`, `"preprod"`, `"preview"`, or `customNetwork(...)` for a devnet. Give a `provider` to read from the chain. One builder serves every transaction.

To build offline, give `params` and `costModels` instead of a provider, and your own UTxOs as the payer: see [Offline and CBOR](/apis/txbuilder/offline). Every option is in [Options](/apis/txbuilder/options).

```tsx
import { TxBuilder } from "@meshsdk/core";

// Online: parameters, UTxOs and outputs are read through the provider
const builder = new TxBuilder({ network: "preprod", provider });

// Offline: nothing is read, so give the parameters yourself
const offline = new TxBuilder({ network: "preprod", params, costModels });
```

`builder.add(...parts)` returns a new builder that also holds those parts, so a function that returns parts is a reusable piece. A part that a transaction holds once, such as `validity` or `message`, held and also given again is `DUPLICATE_PART`.

## Choose the Payer

The payer pays and gets the change. There is no default: without one, `build()` throws `MISSING_PAYER`. Give a wallet, an address or your own UTxOs. A wallet also signs by default.

```tsx
import { output } from "@meshsdk/core";

const pay = output({ address: recipient, value: { lovelace: 5_000_000n } });

// A wallet: its change address and UTxOs are read
const byWallet = await builder.build(pay, { payer: wallet });
// An address: change goes there, its UTxOs are read through the provider
const byAddress = await builder.build(pay, { payer: changeAddress });
// Your own data: nothing is read
const byData = await builder.build(pay, { payer: { changeAddress, utxos } });
```

## Send Lovelace and Assets

`value` maps `lovelace` and units to `bigint` amounts. Leave `lovelace` out and the builder adds the minimum the output needs. Too little is `OUTPUT_BELOW_MIN_COIN`. For several outputs, pass a list: outputs keep their order, and a part that is `false`, `null` or `undefined` is skipped, so `condition && output(...)` works. To attach a datum to an output, see [Smart Contracts](/apis/txbuilder/smart-contracts#lock-assets-at-a-script).

```tsx
import { output } from "@meshsdk/core";

const built = await builder.build(
  [
    output({
      address: recipient,
      value: { lovelace: 2_000_000n, [unit]: 1n },
    }),
    output({ address: partner, value: { [unit]: 1n } }), // no lovelace: the minimum is added
  ],
  { payer: wallet },
);
```

## Build, Sign and Submit

`build()` signs nothing and sends nothing. It returns a `BuiltTx`. `built.tx` is the unsigned transaction as a hex string (CBOR), and `built.txHash` is known before signing. `sign()` signs as the payer, and `submit()` sends through the provider, or through the `submitter` you name.

```tsx
import { output } from "@meshsdk/core";

const built = await builder.build(
  output({ address: recipient, value: { lovelace: 5_000_000n } }),
  { payer: wallet },
);
const { tx, txHash, fee } = built;
await built.sign(); // the payer signs
await built.submit({ submitter: wallet }); // the wallet sends it
const { slot } = await built.awaitInclusion(); // found in a block
```

Never rebuild a transaction to retry it: a new build may pick other inputs, and both could land. Call `submit()` again on the same `BuiltTx`. To change a built transaction, build again with the changed parts and do not send the first one: a built transaction is not edited.

To sign with a private key, with your own code or with several signers, see [Signing and Submitting](/apis/txbuilder/signing).

## Add More to a Transaction

Add these parts to the list you give to `build()`.

### Choose Inputs

The builder picks the payer's inputs. To spend a particular output, add a `spend.pubKey({ utxo })` part. To limit or replace the choice, see [UTxOs and Inputs](/apis/txbuilder/utxos).

### Add a Message or Metadata

`message` writes a message under metadata label 674 (CIP-20, the transaction message standard). `metadata` writes any label. Text in `metadata` is limited to 64 bytes per string. `message` cuts a long text into lines for you.

```tsx
import { message, metadata, output } from "@meshsdk/core";

const built = await builder.build(
  [
    output({ address: recipient, value: { lovelace: 5_000_000n } }),
    message({ text: "Invoice-No: 1234567890" }),
    metadata({ metadataLabel: 1234n, value: { order: "42" } }),
  ],
  { payer: wallet },
);
```

### Set the Validity

`validity({ until })` takes POSIX milliseconds, and `build()` sets no deadline, so give `until` when you follow the transaction yourself. For start times, slots and devnets, see [Time and Validity](/apis/txbuilder/time).

### Require a Signer

`guard.pubKey` names a key that must sign. Scripts see it among the signatories. Give its `address` or its `keyHash`. Keys needed for inputs, certificates and similar are worked out by the builder and listed in `built.signers`.

```tsx
import { guard, output } from "@meshsdk/core";

const built = await builder.build(
  [
    output({ address: recipient, value: { lovelace: 5_000_000n } }),
    guard.pubKey({ address: partner }),
  ],
  { payer: wallet },
);
```

## Plan Several Transactions

`plan()` takes named steps and sends them in order. Use it for several dependent transactions, for retries that cannot pay twice, or to wait for blocks: see [Plans](/apis/txbuilder/plans).

> **Note:** `plan()` needs a provider that returns block heights and the validity flag. The plain `BlockfrostProvider` does not, and `plan()` throws `CANNOT_OBSERVE`: see [Providers and Networks](/apis/txbuilder/networks#use-blockfrost-for-plans).

## Handle Errors

Every error is a `TxError` with a `code`. Check the code, not the message. `TxError.is` also types `error.details`. Build before the `try`, so that a retry calls `submit()` on the same `BuiltTx` and never builds again. Every code, when it comes and which a retry can fix, is in [Errors](/apis/txbuilder/errors).

```tsx
import { output, TxError } from "@meshsdk/core";

const built = await builder
  .build(
    output({ address: recipient, value: { lovelace: 5_000_000n } }),
    { payer: wallet },
  )
  .catch((error) => {
    if (TxError.is(error, "INSUFFICIENT_FUNDS")) {
      console.log(error.details.unit, error.details.missing);
    }
    throw error; // nothing was sent
  });

try {
  await built.sign();
  await built.submit();
  await built.awaitInclusion();
} catch (error) {
  if (TxError.is(error, "SUBMIT_FAILED", "CONFIRM_TIMEOUT")) {
    // the outcome is unknown: call submit() or awaitInclusion() again on this same built
  } else throw error;
}
```
