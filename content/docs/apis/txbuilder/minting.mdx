## Overview

Minting is a part of the transaction: `mint.native` for a native script policy and `mint.plutus` for a Plutus policy. Quantities are `bigint`, and a negative quantity burns.

Examples stop at `build()`: call `built.sign()` and `built.submit()` as in [Transaction Basics](/apis/txbuilder/basics#build-sign-and-submit). They use `builder` and `wallet` from there, and these names, which your application defines:

- `changeAddress` - the wallet's address, from `await wallet.getChangeAddress()`
- `policyCode` - a Plutus minting policy as script CBOR: `applyCborEncoding(compiledCode)` of `@meshsdk/core`, the form `resolveScriptHash` takes
- `referenceAddress` - where CIP-68 reference tokens are kept
- `refTxHash` - the hash of a transaction that holds a script in one of its outputs

## Mint with a Native Script

`ForgeScript.withOneSignature` makes a policy that only your key can use. Give it to `mint.native` with asset names in hex. The policy id comes from the script.

```tsx
import { ForgeScript, mint, stringToHex } from "@meshsdk/core";

const forgingScript = ForgeScript.withOneSignature(changeAddress);

const built = await builder.build(
  mint.native({
    script: forgingScript,
    assets: { [stringToHex("MeshToken")]: 1n },
  }),
  { payer: wallet },
);
```

### Mint Several Assets

Put every asset of a policy in the `assets` of one part. A second part of the same policy is `DUPLICATE_PART` (see [Handle Errors](/apis/txbuilder/basics#handle-errors)). A quantity above `1n` makes a fungible token. A very large collection may not fit in one transaction (`TX_TOO_LARGE`): split it.

```tsx
import { ForgeScript, mint, stringToHex } from "@meshsdk/core";

const forgingScript = ForgeScript.withOneSignature(changeAddress);
const names = ["MeshToken1", "MeshToken2", "MeshToken3"];

const built = await builder.build(
  mint.native({
    script: forgingScript,
    assets: Object.fromEntries(names.map((name) => [stringToHex(name), 1n])),
  }),
  { payer: wallet },
);
```

### Burn Assets

A negative quantity burns. Use the script of the policy that minted the tokens. The tokens must be in the payer's wallet.

```tsx
import { ForgeScript, mint, stringToHex } from "@meshsdk/core";

const forgingScript = ForgeScript.withOneSignature(changeAddress);

const built = await builder.build(
  mint.native({
    script: forgingScript,
    assets: { [stringToHex("MeshToken")]: -1n },
  }),
  { payer: wallet },
);
```

### Mint with a Time-Locked Policy

`script` also takes a `NativeScript` object. This policy works only before a slot, so the transaction states the end of its validity with `validity()`. `builder.slotAt()` turns a time into a slot.

```tsx
import {
  deserializeAddress,
  mint,
  stringToHex,
  validity,
} from "@meshsdk/core";
import type { NativeScript } from "@meshsdk/core";

const { pubKeyHash } = deserializeAddress(changeAddress);
const closes = builder.slotAt(Date.now() + 3_600_000); // a slot in an hour
const policy: NativeScript = {
  type: "all",
  scripts: [
    { type: "before", slot: closes.toString() },
    { type: "sig", keyHash: pubKeyHash },
  ],
};

const built = await builder.build(
  [
    mint.native({
      script: policy,
      assets: { [stringToHex("TimeLocked")]: 1n },
    }),
    validity({ invalidHereafter: closes }),
  ],
  { payer: wallet },
);
```

## Add NFT Metadata

CIP-25, the NFT metadata standard, keeps metadata under label 721, keyed by policy id and then by asset name as text. Add it with `metadata()`. Each text is at most 64 bytes, so split a longer one into a list of strings.

```tsx
import {
  ForgeScript,
  metadata,
  mint,
  resolveScriptHash,
  stringToHex,
} from "@meshsdk/core";

const forgingScript = ForgeScript.withOneSignature(changeAddress);
const policyId = resolveScriptHash(forgingScript);

const built = await builder.build(
  [
    mint.native({
      script: forgingScript,
      assets: { [stringToHex("MeshToken")]: 1n },
    }),
    metadata({
      metadataLabel: 721n,
      value: {
        [policyId]: {
          MeshToken: {
            name: "Mesh Token",
            image: "ipfs://QmRzicpReutwCkM6aotuKjErFCUD213DpwPq6ByuzMJaua",
            mediaType: "image/jpg",
          },
        },
      },
    }),
  ],
  { payer: wallet },
);
```

A royalty token (CIP-27) has the empty asset name and its own entry: `mint.native({ script: forgingScript, assets: { "": 1n } })` with `metadata({ metadataLabel: 777n, value: { rate: "0.05", addr: [first64, rest] } })`. Split the address into strings of at most 64 bytes.

## Mint with a Plutus Script

`mint.plutus` takes the script with its version, a redeemer (the data you give the script) and the assets. Burn the same way with a negative quantity.

```tsx
import { mConStr0, mint, stringToHex } from "@meshsdk/core";

const built = await builder.build(
  mint.plutus({
    script: { code: policyCode, version: "V3" },
    redeemer: { data: mConStr0([]) },
    assets: { [stringToHex("MeshToken")]: 1n },
  }),
  { payer: wallet },
);
```

### Mint CIP-68 Tokens

CIP-68 keeps the metadata in an inline datum (data stored with an output). The reference token (100) and the user token (222) belong to one policy, so they are one part. Lock the reference token with the metadata as its datum; the user token goes to the payer's change.

```tsx
import {
  CIP68_100,
  CIP68_222,
  mConStr0,
  metadataToCip68,
  mint,
  output,
  resolveScriptHash,
  stringToHex,
} from "@meshsdk/core";

const nameHex = stringToHex("MyToken");
const policyId = resolveScriptHash(policyCode, "V3");

const built = await builder.build(
  [
    mint.plutus({
      script: { code: policyCode, version: "V3" },
      redeemer: { data: mConStr0([]) },
      assets: { [CIP68_100(nameHex)]: 1n, [CIP68_222(nameHex)]: 1n },
    }),
    output({
      address: referenceAddress,
      value: { [policyId + CIP68_100(nameHex)]: 1n },
      datum: {
        type: "inline",
        data: metadataToCip68({ name: "MyToken", image: "ipfs://..." }),
      },
    }),
  ],
  { payer: wallet },
);
```

### Mint with a Reference Script

A reference script is a script stored in an output, so a transaction does not send its code again. Name that output instead of the code. The builder knows only the out ref, so give the policy id too. To put a script on chain, see [Smart Contracts](/apis/txbuilder/smart-contracts#deploy-and-use-a-reference-script).

```tsx
import { mConStr0, mint, resolveScriptHash, stringToHex } from "@meshsdk/core";

const built = await builder.build(
  mint.plutus({
    script: { reference: { txHash: refTxHash, outputIndex: 0 }, version: "V3" },
    policyId: resolveScriptHash(policyCode, "V3"),
    redeemer: { data: mConStr0([]) },
    assets: { [stringToHex("MeshToken")]: 1n },
  }),
  { payer: wallet },
);
```
